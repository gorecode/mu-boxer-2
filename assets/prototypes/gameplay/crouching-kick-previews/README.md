# Удар ногой из приседа: три пробы

А — компактный прямой в голень. Б — низкий боковой пяткой с более боковым положением таза. В — подсечка задней ногой с опорой рукой о землю. Автор выбрал **А и В** и поручил интеграцию. Б не подключается.

## Интеграция выбранных вариантов

↓ + N — прямой из приседа (`crouchKick`, 12 урона, без падения); ↓ + назад + N — подсечка с опорой (`crouchSweep`, 17 урона, падение). Есть отдельные сенсорные кнопки и фазы в редакторе разминки. Приёмы выполняются с земли, оба блокируются снизу. Нога и руки сохраняют собственные зоны уязвимости. Перемещения корня нет, удержание кнопки не повторяет удар. При отпускании ↓ во время приёма герой завершает его в приседе, затем возвращается в стойку.

Точные четыре выбранных PNG подключены как lossless `boxer-21..24.webp`, origin(240,485), scale1.19. `export-runtime.py` проверяет полное RGBA и сохраняет хеши в `runtime-assets.json`. Сохраняется ритм подготовки80 → контакта120 → быстрого возврата40 мс; далее исходный присед. Полное восстановление:440мс у прямого,620мс у подсечки. Дальняя граница активной зоны:256 и379 мировых пикселей соответственно; запас за видимым носком19,19 и18,43 пикселя. На возврате урона нет.

GIF находятся в `scene-lab/public/previews/crouching-kicks/`: `a-straight.gif`, `b-side.gif`, `c-sweep.gif`, общее `comparison.gif`; каждому соответствует `-slow.gif` с замедлением ×4. `decoded-sheet.png` показывает декодированные присед, подготовку и контакт.

Мастер — реально используемый при приседе `scene-lab/public/art/fight/boxer-5.webp`, дополнительный референс анатомии — `boxer-0.webp`. Источники новых рисунков созданы встроенным image_gen: три прозрачных двухкадровых листа в `inputs/`. Точные задания — `prompts.json`. Это новые ключевые рисунки, а не исправление или замена ранее утверждённых ударов.

Экспорт переиспользует упаковщик и проверки GIF из `../kick-previews/export.py`. PIL используется для разделения листов, регистрации, размещения на общей арене и упаковки, без перерисовки персонажа. Оригинальный присед переносится без изменения масштаба и RGBA. Каждый новый лист уменьшается одним коэффициентом для обеих поз; регистрация идёт по опорному ботинку. Коэффициенты и координаты находятся в `export.py` и `verification.json`. Разделение листа на x620 учитывает фактические границы фигур вместо формального деления пополам, которое срезало бы опорную руку подсечки.

На вариант три уникальных рисунка: исходный присед, подготовка и контакт. Петля1600мс: присед560 → подготовка80 → контакт120 → возврат через подготовку40 → присед800. Тайминги всех вариантов одинаковы; новые игровые окна урона не назначены. Морфинга и растворений нет.

При первичном отсмотре проверены целые головы, два ботинка, связи коленей и опора руки. В подсечке голова и таз опускаются вместе; в боковом корпус смещается к опорной ноге. Изменения силуэта и складок — результат новых рисунков, пиксельная идентичность оригиналу для них не заявляется. Естественность и окончательный выбор оценивает автор.

Повторная сборка:

```bash
python3 assets/prototypes/gameplay/crouching-kick-previews/export.py
```

Экспорт проверяет непустые опоры, отсутствие обрезки непрозрачного силуэта, исходный присед, разные фазы, длительности декодированных GIF, бесконечный луп и одинаковые начало/конец. Хеши входов и выходов записываются в `verification.json`.

Проверка: экспорт успешно декодировал восемь GIF; typecheck и lint приложения прошли. В системном Chrome открыто общее замедленное сравнение, последовательные снимки подтвердили смену приседа и подготовки. Контакт отдельно отсмотрен на декодированном листе; непрерывный человеческий отсмотр движения этим не заменён. В первоначальной проверке исходника обнаружилось изменение RGB полностью прозрачных пикселей при alpha_composite; для исходного приседа применён прямой перенос paste, повторная проверка полного RGBA прошла.

Проверка интеграции: `npm run check` — typecheck, lint,277 unit-тестов и production-сборка прошли.46 браузерных проверок новых приёмов, прежних прямых ногами, спецприёмов и стоящего апперкота прошли на desktop и Pixel7/360px. Новые проверки покрывают реальные ↓+N и ↓+назад+N, отпускание ↓, удержание кнопок, сенсорные сокращения, однократный урон, низкий блок, редактор и повторную загрузку отсутствующего рисунка. Контакты отсмотрены на снимках реального Canvas. Для браузерной проверки использовался отдельный preview на4507: штатный4197 был занят другой сборкой.
