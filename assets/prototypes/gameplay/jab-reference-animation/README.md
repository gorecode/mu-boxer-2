# Джеб из исходных текстур по движению видео

Лучший результат самостоятельного отсмотра после восьми итераций. Авторское утверждение новой анимации ещё не получено. Полнотелые перерисовки и независимый поворот кисти отбраковали; сохранён риг с исходными текстурами и сокращением перспективы между оригинальными позами.

- `jab-in-arena.webp` — результат в игровом Canvas; `comparison.webp` — синхронно исходный джеб / отвергнутая перерисовка / результат.
- `contact-comparison.png` — контактные рисунки без GIF-квантизации; `baseline-*.webp` — зафиксированные исходные сравнения из игры.
- `inputs/` — точные исходные текстуры; `frames/` — 18 прозрачных кадров 500×530 в родной пиксельной сетке, общий origin (164,495), scale 1.19 только в рендере.
- `video-motion.json` — источник и приблизительные ручные оценки суставов видео. Движение ретаргетировано и ускорено художественно; покадровое совпадение всех суставов с видео не заявляется. RGB видео не используется.
- `metadata.json` — суставы, длины проекции и ритм; `verification.json` и `export-verification.json` — результаты проверок.
- `rig.mjs` — параметры масок и детерминированная сборка. Контактный вид руки и вид из стойки берутся из оригинальных текстур. Новая генерация в итоговых кадрах не используется.
- `rejected-joint-generation.png` — неудачная генерация всего листа; причины отбраковки и промпты находятся в навыке.

Лицо, футболка и ноги сохраняют исходный рисунок. Проверены 5364 пикселя лица с alpha ≥250, побитное совпадение нижней области и возврат в исходный кадр. В игровом Canvas максимум расхождения лица — 1 значение канала на сглаженном краю, внутренняя область тела совпадает точно; край прежней обрезки текстуры может отличаться по AA на одну строку/колонку. Кончик кулака доходит до 248 игровых px; исходный контакт — примерно 255, отвергнутая перерисовка — 297. Выход 80 мс, контакт 80 мс, возврат 180 мс. На первом кадре возврата контактная поза уже отпущена.

## Воспроизведение

Из корня репозитория, с установленными зависимостями `scene-lab` и Pillow:

```sh
python3 -m http.server 4201 --bind 127.0.0.1
```

Открыть `/assets/prototypes/gameplay/jab-reference-animation/preview.html`: проигрывание, пауза, ¼× и ползунок. В другом терминале:

```sh
node assets/prototypes/gameplay/jab-reference-animation/bake.mjs
python3 assets/prototypes/gameplay/jab-reference-animation/verify.py
node --test .claude/skills/video-reference-animation/scripts/retarget.test.mjs assets/prototypes/gameplay/jab-reference-animation/preview.test.mjs
node assets/prototypes/gameplay/jab-reference-animation/capture.mjs
python3 assets/prototypes/gameplay/jab-reference-animation/export.py
```

`capture.mjs [URL игры]` временно подставляет 18 кадров в рисунки джеба через браузерный перехват рисования. Используются реальные часы приёма из `data-player-action-time`; выбирается последний кадр, время которого уже наступило. Источник изображения и масштаб читаются из текущей игры. Этот стенд проверен с опубликованным `fight-CC85Y72N.js`; при изменении рендера адаптируйте проверку. Скрипт требует непустого набора реально нарисованных кадров.

GIF 1×/¼× и сырые снимки будут в игнорируемой `.capture/`; WebP и контактный PNG обновятся рядом с этим файлом. Для тонкой штриховки смотрите PNG; GIF использует общую палитру сравнения.

## Граница интеграции

Это воспроизводимый визуальный пример, проверенный в игре через временную подстановку. Опубликованные боевые файлы и правила не изменены. Runtime пока ожидает восемь рисунков; для 18 кадров потребуется выбор по временным меткам. При интеграции заново настройте BB: запас около 18 px за новым кулаком даёт правую границу примерно 266 px вместо 315 у отвергнутой перерисовки. Проверьте отмены, дальность, блок, hitstop и зеркальное направление после подключения.

Навык: [video-reference-animation](../../../../.claude/skills/video-reference-animation/SKILL.md). Он описывает применённый метод и его границы, не выдаёт самостоятельный отсмотр за утверждение автора.
