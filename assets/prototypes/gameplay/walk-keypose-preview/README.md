Предпросмотр от 22 ноября 2026 года. **23 ноября автор выбрал четыре рисунка для геймплея; этот вариант интегрирован в бой.** Сравнение двух и трёх рисунков сохранено как эксперимент. До изготовления вариантов выполнено [исследование игр и практик анимации](../../../../docs/research/SPRITE_WALK_CYCLES.md).

Слева направо: два, три, четыре уникальных рисунка **полного подшага**, а не FPS. Во всех колонках одинаковы исходные текстуры, масштаб, скорость корня 355 игровых px/с, подшаг 134 px, маршрут вперёд/остановка/назад и палитра. Два цикла вперёд и два назад, по 268 px. Темп цикла сохранён от текущей ходьбы: примерно 377 мс. Растровые рисунки меняются дискретно; межкадрового смешивания при воспроизведении нет.

| Вариант | Доля цикла → рисунок | Назначение |
| --- | --- | --- |
| 2 | 0 → A, ½ → C | Стойка и расширенная опора |
| 3 | 0 → A, ½ → C, ¾ → D | Дополнительно задняя нога восстанавливает стойку |
| 4 | 0 → A, ¼ → B, ½ → C, ¾ → D | Дополнительно виден перенос передней стопы |

При отходе рисунки идут в обратном порядке, герой продолжает смотреть вправо. Исходная стойка возвращается на остановке. Маршрут заканчивает движение после целого числа циклов; остановку посреди подшага это сравнение не проверяет. Все варианты вложены в один набор ключей; добавление рисунков не меняет длительность подшага. Вариант 2 — новый контроль из согласованного набора A/C, **не запись опубликованного чередования boxer-0/boxer-1**.

## Исходники и две итерации

1. Встроенный imagegen изготовил четыре полнотелые позы. С исходным верхом тела они были собраны для первого сравнения. При проверке декодированного GIF обнаружено несоответствие стоп пройденной дистанции. Источник, точный промпт и параметры совмещения сохранены в `inputs/`, `PROMPTS.md` и `generation-v1-registration.json`. Это отклонённый эксперимент, а не дополнительный утверждённый мастер.
2. Итоговый набор запекается из единственного `boxer-0.webp`, SHA-256 `4ecabf66657cf73ae3f86bf1eb70afb293cf5758dc23c0f671b96d2785dd614d`. Нативное поле деформации в `rig.mjs` разводит ноги, сохраняет цельные ботинки и переносит исходный верх без вращения или масштабирования. Вертикальный ход верха — 0/4/8/4 исходных px; передняя стопа поднимается на 6 px в B, задняя на 5 px в D. Сгенерированные пиксели в итоговую анимацию не вошли.

У запечённых PNG общий холст 500×530, origin (228,495), включая 64 px дополнительного поля слева, масштаб игры 1.19. `preview.mjs` уменьшает весь игровой вид до 65% один раз для трёх колонок. Геометрия рига и контрольные точки — в `rig.json`, проверки — в `verification.json`.

## Что проверено и что остаётся ограничением

Проверены девять тестов последовательностей, начального состояния, границ, остановки, реверса, ошибочных входов, опор и обратного отображения текстуры. Браузер сохранил 136 контрольных изображений без ошибок JS; число показанных рисунков — ровно 2/3/4. Все RGBA-пиксели верхних 218 строк совпадают после обратного учёта общего сдвига, включая 23 382 пикселя с alpha ≥250. Изображения не обрезаны краями холста; в каждой позе есть опора.

Каждый готовый GIF декодирован и попиксельно сопоставлен с общей индексированной палитрой на всём таймлайне. Проверены длительность, бесконечный луп и совпадение начального/конечного изображения. Экспорт использует прозрачные разницы кадров с сохранением предыдущего изображения: исходная 33 MB упаковка уменьшена примерно до 9,5 MB без дополнительного изменения цветов.

При отсмотре декодированных состояний четыре рисунка яснее показывают отдельные переносы ног; три сохраняют более резкие смены силуэта; два сильнее перескакивают между опорами. Это оценка агента. После сравнения автор поручил интегрировать вариант с четырьмя рисунками. Формальную проверку не выдаём за доказательство естественности.

В опорных ключах положение задней стопы на первом полушаге и передней на втором согласовано с корнем. Между ключами корень продолжает двигаться, а рисунок удерживается, поэтому остаётся скольжение. Риг деформирует плоскую текстуру, а не сохраняет анатомические длины костей через IK. Проверка обратного отображения доказывает корректность выборки текстуры, не анатомию. Эти ограничения сохраняются в интегрированном варианте.

## Интеграция в геймплей

`export-runtime.py` экспортирует четыре PNG без изменения RGBA в `scene-lab/public/art/fight/walk/walk-0.webp`–`walk-3.webp` и обновляет manifest. Хеши и результат проверки сохранены в `runtime-assets.json`. Браузер загружает готовые текстуры; риг при игре не выполняется. Нулевой рисунок совпадает с исходной стойкой с учётом дополнительного поля 64 px.

Модель хранит отдельную фазу `Fighter.walk` от 0 до 134 px. Она считается по разрешённому смещению после столкновений, изменяется со знаком направления относительно противника и обновляется до проверки попаданий. Так рисунок и зоны используют одну фазу. У стены фаза сбрасывается в стойку; при смене направления цикл обращается; после остановки начинается новый подшаг. Старый общий `travel` не управляет ходьбой ГГ. Пауза, hitstop и снимок тренировки сохраняют фазу. Вход в действие, защиту, присяд, отскок, полёт или реакцию прерывает ходьбу без задержки управления.

Для четырёх поз заданы раздельные зоны ног и снижение головы; зеркальность использует те же мировые преобразования, что остальные зоны. Восемь модельных тестов проверяют фазы, переходы, стены, раздвигание тел, реверс, заморозку, сохранение, завершение раунда, уязвимость и неизменность исходников. Семь браузерных сценариев на двух размерах экрана проверяют реальную отрисовку, отход, остановку посреди шага, переходы, полученный удар, восстановление момента, зеркало, стену и ошибки загрузки. [Кадр из игры с зонами уязвимости](runtime-walk.png).

## Воспроизведение

Из корня репозитория, Node 24, зависимости `scene-lab` и Python 3 с Pillow:

```sh
node --test assets/prototypes/gameplay/walk-keypose-preview/*.test.mjs
node assets/prototypes/gameplay/walk-keypose-preview/capture.mjs
python3 assets/prototypes/gameplay/walk-keypose-preview/verify.py
python3 assets/prototypes/gameplay/walk-keypose-preview/export.py
python3 assets/prototypes/gameplay/walk-keypose-preview/export-runtime.py
```

`capture.mjs` временно поднимает HTTP-сервер только на 127.0.0.1, использует установленный Chrome, закрывает сервер и браузер после захвата. Промежуточные снимки и декодированный контактный лист находятся в игнорируемой `.capture/`. Боевые определения и загрузчик арта используют экспортированные WebP и метаданные, без импорта скриптов предпросмотра.
