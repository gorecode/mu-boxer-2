# Подсечка с разворотом: три GIF-пробы

Запрос автора: попробовать вращение с промежуточным рисунком спиной к камере.
Автор выбрал **А** и поручил интеграцию с доработкой таймингов. Управление сохранено: ↓ + назад + N и сенсорная кнопка.

- **А — разворот перед контактом:** присед → опора → задние три четверти → спина → исходный контакт → опора → присед.
- **Б — доворот после контакта:** присед → опора → исходный контакт → спина → задние три четверти → опора → присед.
- **В — круговая подсечка:** присед → опора → спина с ногой влево → боковой разворот с ногой вправо → исходный контакт → опора → присед.

GIF: `scene-lab/public/previews/sweep-turns/`, файлы `a-windup.gif`,
`b-follow.gif`, `c-circle.gif`. Рядом замедление ×4 (`-slow.gif`), прежняя
версия (`old.gif`) и декодированные листы (`-decoded.png`).
Все циклы1600мс, одинаковые арена и исходные рисунки. Внутренние тайминги
разные: это сравнение схем движения, а не игрового баланса.

Исходные три рисунка из `crouching-kick-previews/frames/` перенесены
целиком с сохранением RGBA, без масштабирования. Новые задние ракурсы
сделаны built-in imagegen по этим трём мастерам, не плоским вращением
картинки. По два новых рисунка на вариант, всего пять уникальных рисунков.
Пропорции и палитра новых рисунков приблизительные и требуют выбора автора.

`prompts.json` содержит точные промпты; `inputs/` — нетронутые генерации;
`registration.json` — постоянный масштаб пары и положение опорной ладони;
`frames/` — зарегистрированные новые позы. Исходная сетка640×550 расширена
до840×550, чтобы левая фаза кругового движения не обрезалась.

Сборка: `python3 assets/prototypes/gameplay/sweep-turn-previews/export.py`.
Скрипт проверяет непустую альфу, границы фигуры, сохранение исходного RGBA,
декодированные длительности, непрерывный loop и замедление ×4.
Хеши и расписание записаны в `verification.json`.

Отсмотр: у исходного приёма отсутствовал задний ракурс → добавлены разные
фазы разворота. В А читается замах, в Б — инерция после контакта; в В самый
заметный перепад между задней и боковой проекциями. Поворот остаётся
комиксным, дискретным; естественность полного круга не подтверждается
проверками упаковки. Возврат использует прежнюю опорную позу, без нового
заднего рисунка. Автор пока не выбрал вариант.

Chrome воспроизводил готовые GIF; сохранены24снимка и видео в
`/tmp/sweep-turn-playback/`, сведения в `playback.json`. Визуальный вердикт
основан на декодированных позах и выборочных кадрах воспроизведения.

## Интегрированный вариант А

`a-integrated.gif` и `a-integrated-slow.gif` показывают окончательный ритм:
опора50 → задние три четверти60 → спина40 → контакт100 → возврат60 мс.
Далее310мс восстановления в исходном приседе; полный приём620мс.
Замах150мс вместо исходных80мс; активное окно100мс вместо120мс.
Урон17, дальность444, низкий блок, сбивание и hitstop55/85мс сохранены.
GIF показывает движение на промахе; hitstop при попадании добавляется игрой.

В runtime точные `frames/a0.png` и `a1.png` экспортированы без изменения RGBA
как `boxer-26.webp` и `boxer-27.webp`. Origin(380,485), scale1.19 учитывает
расширенную сетку: x380 соответствует x240 исходных поз. Регистрация совпадает
с выбранной пробой. `export-runtime.py` повторяет экспорт и проверяет RGBA.
Два задних рисунка имеют отдельные зоны уязвимости, но не наносят урон.
Возврат также не наносит урон. Общая длительность сохранена, однако более
длинный замах намеренно делает подсечку заметнее до попадания.

Проверено после интеграции:278 unit-тестов, typecheck, lint и production-сборка.
Из64 целевых браузерных тестов61 прошёл первым прогоном; два превысили30с,
ещё один попал на перезагрузку dev-сервера во время правки hurt-зон. Все три
прошли отдельным повтором без изменения тестов при двух workers. Прямой ввод
↓ + назад + N отсмотрен на игровом Canvas: опора, задние ракурсы, контакт и
возврат; снимки `/tmp/sweep-runtime/`. Это не проверка на физическом телефоне.
